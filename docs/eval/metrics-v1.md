# 评测 V1：五项能力指标与首批开发题

2026-10-19 作者确认口径。适用于首批 20 道回归题、70 道新开发题和封存 30 道测试题；覆盖本项目主要失败类型，不宣称测出了数学上可定义的“80% 全部能力”。

**这是评测契约，不是已完成的自动评分功能或实测结果。** 当前实现和待补能力见第 7 节；实际交付证据只认 [build-log](../../harness/build-log.md)。

## 1. 五项指标，计数单位固定

每道可回答题先从冻结原文提取 2～4 个原子关键点，标 `vital`（必须有）或 `okay`（有更好）。问题本身必须要求这些信息，不为凑数量拆碎事实。本文“必答点”均指 vital。

| 指标 | 单题公式 | 适用题与判据 |
|---|---|---|
| **最终证据覆盖率 E** | 最终生成上下文完整支持的必答点数 / 全部必答点数 | 可回答题。看实际送给生成模型的资料，不用“找到了正确文章”代替 |
| **答案要点覆盖率 A** | 最终回答完整覆盖的必答点数 / 全部必答点数 | 可回答题，沿用现有 `V_strict`；部分覆盖单列但不计完整 |
| **事实有据率 F** | 正确、版本条件适用且被本次生成上下文支持的事实声明数 / 全部可核验事实声明数 | 检查系统实际说出的内容，包括额外补充；不能只检查必答点 |
| **有效引用覆盖率 C** | 获得正确、充分引用支持的事实声明数 / 回答中应引用的事实声明数 | 检查声明与引用证据的对应；漏引、错引分别记原因 |
| **边界题处理正确率 B** | 达到类别可接受行为的题数 / 全部边界题数 | 拒答、澄清、纠正前提等；不要求实际 `route` 字符串等于预期标签 |

要点描述必须具体，例如“自部署版单次最多上传 5 个文件”，不能写“正确解释上传限制”。完整支持包括必要的数值、对象、适用条件；允许措辞变化和有证据的逻辑推导。

事实声明按可独立核验的数值、条件、操作方法或结论拆分；礼貌用语不计，同一个事实重复出现只算一次。不因回答长就加分。对声明记录“有据 / 矛盾 / 证据不足”、证据位置和简短理由；缺少支持不等于已经证明现实中为假。

引用针对**回答中的声明**，不要求每个检索 chunk 都被引用。多跳结论允许一组引用共同支持；仅有 `[1]`、链接可打开或引用编号存在，都不算支持成立。版本不符、无法定位、只支撑一半或夹带无关引用的证据组，要指出问题，不记作完整有效支持。

### 空值与分母

- 可回答题正常拒答：A=0。若曾实际执行生成，E 按对应上下文核验；没有生成资料交付时 E=0，不从 grade 阶段的候选资料虚构生成上下文。
- 没有实质事实声明的合理拒答 / 澄清：F、C 为 N/A，不能记 100%。有明确事实断言时仍核验这些断言。
- 应有引用而没引用：该声明的 C 分子为 0；没有应引用的事实声明时 C=N/A。
- 可选 okay 关键点另列，不替代 vital。边界题 E、A 不适用，B 单独计算。
- 系统失败、评审异常、记录缺失属于未完成项，不伪装成正常拒答，不默默剔除后只报高分；同时报告全量题数、执行完成数、评审完成数、N/A 和失败数。当前旧总分只汇总成功评审题，必须与完成情况一起读。
- 先算单题比例，再对适用题做**宏平均**，防止长答案或关键点多的题主导结果；同时展示单题原始计数和有效题数。B 等价于边界题 0/1 的平均。

无检索基线没有外部上下文，E=0、F 不会因模型凭记忆答对而算“有上下文支持”；这反映 grounding，不等于独立事实准确率为 0。其事实正确性仍由原有总分对照金标文档判断。现有 naive 基线没有强制引用指令，C 只描述其引用表现，不能据此宣称完整系统的事实正确性更高。

## 2. 沿用原有总分，不重新加权

沿用 [scoring.py](../../backend/eval/scoring.py) 的规则；五项比例不随意混合成另一个总分，也不能据 F 直接反推旧总分。

| 情况 | 原有分数 |
|---|---:|
| 可回答题：没有作答（拒答或反问） | 0 |
| 可回答题：作答但有矛盾，或存在无依据的具体说法 | −1 |
| 可回答题：没有上述问题，所有 vital 完整覆盖 | +1 |
| 可回答题：没有上述问题，至少一条 vital 完整或部分覆盖 | +0.5 |
| 可回答题：其他答不到点的回答 | −1 |
| 边界题：达到该类别可接受行为 | +1 |
| 边界题：其他 | −1 |

边界行为：库内缺依据 / 无关 / 注入 → 拒答；错误前提 → 纠正；含糊 → 反问或覆盖合理解释。库内缺依据题可能先走 SINGLE 再 abstain，路由标签不代替最终行为。

总体可信得分为成功评审题的 points 平均，沿用现有 bootstrap 95% 区间，注明分母和未完成项。旧代码把可回答题 `incorrect` 占比命名为 hallucination；它包含“答不到点”等情况，**不能把它当作新的逐声明无依据率**。

原有 Recall@5 保留检索附表：当前代码检查前五篇返回文档是否**全部**包含 gold_docs，属于文档全命中率；不是逐 chunk 召回比例，也不是完整多查询结果经过一次全局精排的前五。MRR、路由准确率等已有输出可以保留，不增加为本轮主指标。

P95 延迟和每题生成成本自动附带；标记冷启动、缓存、降级与异常。现有成本不包含评审用量，不冒充总实验费用。

## 3. 计数例子（假设，不是实验结果）

必答点为 A / B / C；最终上下文有 ABC；回答正确说出 AB，漏掉 C，又编造 D；三条应引用声明中只有 A 引用有效。

| E | A | F | C | B | 原有总分 |
|---:|---:|---:|---:|---|---:|
| 3/3 = 100% | 2/3 ≈ 67% | 2/3 ≈ 67% | 1/3 ≈ 33% | N/A | −1（存在无依据 D） |

证据已经充分，主要问题在生成和引用。若 E 也低，才沿 trace 排查召回、精排、父块扩展和上下文截断。

## 4. 标准与运行结果分开保存

每题准备两份清单：

1. **出题清单**：问题 ID、题型、版本、预期行为、2～4 个要点、原文摘录、文档 / 标题 / 父块 / 子块 ID、等价证据组、冻结语料与切分版本。参考答案供人阅读，不做整篇答案字符串相似度评分。边界题解释原因和可接受行为。
2. **评审清单**：各要点的上下文支持和回答覆盖；每条回答声明的支持状态、实际证据、引用与判据；原有总分、异常及人工复核。声明核验覆盖完整回答，详述失分原因即可，不另建复杂加权体系。

先从原文确立标准，再运行被测 RAG。不能让系统自己的答案、grade 或 verify 直接充当评测真值。库内缺依据也不能仅由一次检索没找到来证明。

gold_docs 沿用已有数据结构；等价来源另记侧表，不把“任选其一”的多篇文档全部塞进要求全命中的字段。真实 chunk ID 从现有数据核对，不能编造；ID 会随重新切块改变，因此同时保存原文摘录、语料 commit 和 `INGEST_VERSION`。

过程记录继续使用现有 Step / RetrievalResult：子问题、逐轮候选、精排、父块、缺失信息、实际生成上下文、每次生成、校验、执行过的后处理及缓存 / 降级。它们用于错题归因，不逐阶段再加一整套主指标。最终回答经后处理改变时，核验最终展示内容，并保留它所对应的生成资料。

## 5. 首批 20 题回归集与 70 开发 + 30 测试如何看

| 阶段 | 用途与读取方式 |
|---|---|
| 首批 20 回归 | 2026-10-19 起只作回归检查：系统改动后不得变差，不计入 70 开发题，也不用来衡量系统强弱。7 事实、3 归纳、4 跨篇、2 版本、4 边界（含糊 / 无关 / 注入 / 库内缺依据各一）；逐题复核，发现链路问题，校准评审，分组显示题数，不从细小分差得出提升结论 |
| 新开发集 70 | 重新出 70 道，不含首批 20；难度轴、配额见 dev20/README 之后的出题指令；相同指标与评审版本反复比较系统，按题型 / 版本 / 措辞报告，改模型或 Prompt 后隔离旧缓存 |
| 封存 30 test | 存仓库外，开发 agent 不读取；系统与评分规则固定后由作者运行，不能据它继续调参 |

20 回归 + 70 dev + 30 test 共 120 题运行；对外只报 70 dev 与 30 test 的分数，回归 20 单独看是否退步。70 dev 与 30 test 分别报告，不能混报一个最终正确率。DIRECT 闲聊另外手工检查，不占正式题量。

首批开发题入口为 [dev20/README.md](dev20/README.md)。题目是待作者审阅的草案，不因格式校验通过就视为金标无误。审核后冻结题集版本；再运行只检索诊断，然后用同题比较 naive 与 full。只检索模式没有路由、改写或分解，不能代替完整系统。

首批 20 题回答做人工复核；现有 ≥85% 一致率是校准起点，不是论文证明的普适阈值，还要看错误数值、错版本、漏点、无据扩写和合理拒答是否被识别。尽量用独立于生成方的评审模型，固定评审版本，分歧和异常由作者裁决。增加题量后继续复核异常并随机抽检。

## 6. 论文如何组合，以及为什么不继续加指标

| 来源 | 借鉴到本项目的内容 | 本轮范围 |
|---|---|---|
| [FreshStack，NeurIPS 2025 D&B](https://proceedings.neurips.cc/paper_files/paper/2025/hash/e6b5bcc872666d37c469e5c5ba723669-Abstract-Datasets_and_Benchmarks_Track.html) | 建立要点与支持证据的对应，区分找对文章与找到必要信息 | E 与出题证据侧表；不标全部语料 chunk 的相关性 |
| [RAG-Zeval，EMNLP 2025 主会](https://aclanthology.org/2025.emnlp-main.1267/) | 把回答分成声明，以证据判断支持性；区分正确性和忠实性 | F 的核验思路；不训练论文的强化学习评审模型 |
| [Demystifying Deep Search，ICLR 2026 主会](https://proceedings.iclr.cc/paper_files/paper/2026/hash/9a27f07ee41dd59d527062e045c16353-Abstract-Conference.html) | 分开证据充分性、证据利用和拒答行为 | E / A / B 的诊断；不照搬 Wikipedia 沙盒搜索评分 |

组合是工程适配：原有答案要点评分与总分继续使用，补上证据、事实和引用的可核验计数。有效引用率 C 来自项目“答案带出处”的明确需求，不声称是三篇论文共同提出的公式。RAG-Zeval 的零人工标注主要指训练方法，不代表不需要独立正确依据。

不新增文风、表达优美、多模型评审团、逐轮指标矩阵；不要求所有召回 chunk 被使用。五项指标覆盖检索交付、生成遗漏、无据扩写、引用和边界处理，原始过程足以支持进一步定位。
