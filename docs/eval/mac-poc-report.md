# Mac 本机实测报告

本报告汇总同一台 Mac 上的工程指标、LangGraph 和 Dify V3 的合成开发题对照，以及 42 道日文规程开发题的实测。规程评审校准为 16/20（80%），低于 85% 门槛，规程回答通过率与离线可采纳率为未测。封存结果待作者运行。

## 运行条件

- Apple M4 Max，64 GB 统一内存；Docker Desktop 分配 24 GiB，运行时观察到约 23.43 GiB。Qwen3 嵌入和精排用 MPS。小模型 Ollama Qwen3 4B Instruct 在本机运行，生成模型为经 LiteLLM 转发的 DeepSeek V4 Pro。 [Mac 环境记录](../../harness/context/phase-30-mac-context.md)
- 两侧使用同一台 Mac、同一网关及模拟业务系统，在各自预热两次后串行回放。LangGraph 与 Dify 分两次运行，DeepSeek 由同一网关转发。延迟按客户端 HTTP 请求起算，整段计到各自的答复结束事件。第一版的 Windows 数字留在历史记录。 [阶段 36 证据](../../harness/build/phase-36-evaluation.md#记录) · [Dify 回放步骤](dify-local.md#回放证据)

## 已知边界

- 模拟业务、权限和故障注入只反映本机样例。真实贷款审查、费率承诺、写入业务、线上流量、灰度切流和生产回滚都在本项目范围外。
- 坐席混合意图实现查数与规程组合，其他组合未覆盖。流式输出收到完稿后做校验，必要时以撤回事件替换已显示片段。
- LiteLLM、数据服务和 Dify 都在本机。生成走外部 API；配置 Langfuse 时沿用现有云端选项。
- Dify 和 LangGraph 使用同一嵌入权重，LangGraph 的查询另加日文任务指令。Dify 已核验混合索引和画布，语料的生效时间字段未回填至结构化元数据。Dify 过期候选由已映射的文档 ID 识别，答复引用计数也依赖回放器识别的文档 ID。 [Dify 平台能力核对](../../infra/dify/chatflow.md#平台能力核对)
- 调优候选扩大了可按一般规程作答的范围。静态审查发现，个人住宅贷款减税判断和还款困难商谈的专门窗口转介仍需验证。现有提示与通用护栏缺少对这两类请求的专门处置。本轮没有观测到实际违规答复，调优版保留为本地开发候选。 [合规边界](../../GOALS.md#合规边界) · [候选验收记录](../../harness/build/phase-36-evaluation.md#记录)
- 仓库为公开仓库。当前实现与验收提交保存在本机，是否推送由作者决定。
