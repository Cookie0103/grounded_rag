## 怎么读这些数

- 两套系统跑在同一台 Apple M4 Max（64 GB 统一内存，Docker Desktop 分配 24 GiB）上。配对回放共享题目、LiteLLM 网关和模拟业务系统，各自预热后串行执行。阶段 37 的 Dify V3 实例是 Dify 1.19.0。S 档语料 185 篇，L 档 3,000 篇。第一版的 18～32 秒 P95 来自 Windows 和 RTX 5070 Ti，单独留作历史记录。 [Mac 环境](../../harness/context/phase-30-mac-context.md) · [Dify 本机手册](../eval/dify-local.md)
- 首字是 HTTP 请求发出到首段回答文本的时间。整段计至答复结束，Dify 取 `message_end`，回放另等 `workflow_finished` 收齐节点证据。请求间的限流等待在计时之外。每个节点只统计实际经过该节点的请求，P95 不能相加。正式报告以同题为单位做 1,000 次 bootstrap，随机种子为 0。小模型与流式冒烟另有最近秩估计。 [阶段 35](../../harness/build/phase-35-streaming-guard.md#记录) · [阶段 36](../../harness/build/phase-36-evaluation.md#记录) · [阶段 37](../../harness/build/phase-37-dify-compare.md#记录)
- 成本是网关观察到的 token 用量按本地账本计价。DeepSeek 采用高峰、缓存未命中单价保守记账，本机 Ollama 和嵌入不计 API 费用。报告单会话成本与整个账本增量的分母不同，后者还可包含预热和诊断。没有测月度结算金额、主机成本或真实运营成本。 [计费实现](../../backend/app/providers/deepseek.py) · [Mac 环境](../../harness/context/phase-30-mac-context.md)
- 意图按有金标的题计数。合成回归按适用的意图、工具、证据及护栏等断言判断。工具失败率按最终调用状态计数，分母包括鉴权拒绝。规程 Top5 只按 37 道可回答题计召回，过期命中在 8 道版本陷阱上计。正式回答质量需要独立评审达到校准门槛。 [评测口径](../../harness/build/phase-36-evaluation.md) · [报告实现](../../backend/eval/copilot_report.py)

## 差异从哪里来

- 首字最明确的差别来自输出链。LangGraph 在生成过程中推送文本，末尾完成规则检查，需要时再发送撤回。发布的 Dify 画布在生成节点产出后进入答复节点，185 条无注入中超出首字目标的答复有 50 条以生成节点为最慢、1 条以意图节点为最慢。这解释了为何首字差异明确，整段配对区间含零。 [流式验收](../../harness/build/phase-35-streaming-guard.md#记录) · [Dify 画布](../../infra/dify/chatflow.md)
- 两侧小模型来自同一网关，示例、路由识别和执行开销仍有差异。185 条无注入合成的意图对照中，Dify 将 8 条规程误判为查数，LangGraph 将 2 条规程误判为查数、2 条查数误判为规程。Dify 平均 token 更多但生成节点样本更少，实测平均费用也更低。费用还受实际收费模型调用和模型用量影响。 [同题汇总](../eval/mac-poc-report.md#s-档同题对照)
- LangGraph 实现了独立工具并行、工具与检索重叠、一次重试及熔断，Dify 使用已核验的 37 节点常规混合检索画布。Dify 画布把查询日期提供给生成提示；其检索端未应用同一结构化生效日期过滤。两侧索引、分段和查询输入也不同。结果适用于这两套实现与配置。 [工具验收](../../harness/build/phase-33-tools.md#记录) · [Dify 能力核对](../../infra/dify/chatflow.md#平台能力核对)
- 还款困难早于首轮调优就存在漏转，`11ba76a` 和 `f01605e` 原三题均为 0/3。后续两项专门转介按合规边界修复，独立测试覆盖常规手续和投诉反向用例。个人减税旧版三题曾在 3/3、2/3 与 1/3 之间波动，逐条失败归因为遗漏专业渠道或引用护栏撤回。最终版改为固定去向并验证两处撤回兜底。 [转介修复](../../harness/build/phase-38-wrapup.md#记录)
