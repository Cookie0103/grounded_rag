# 开发日志

按天记录开发过程，出了问题可以回溯。每天一个文件夹，文件夹名就是日期。

```text
implementation-log/
├── README.md              # 本文件：规则与索引
└── 2026-10-16/
    ├── README.md          # 当天记录（必有）
    └── notes-*.md         # 当天的阅读笔记（可选，资料多时单独成文）
```

## 规则

- 日期按东京时间（作者所在时区）的自然日，格式 `YYYY-MM-DD`，与当天分支名的日期一致（见 [workflow §3](../workflow.md)）。
- 同一天多个会话追加到同一个 README，不新建文件夹。
- 收工前必须写好当天的记录，没写日志的一天不算完成。
- 写简要即可，但三件事不能少：**遇到了什么困难、查了什么资料、怎么解决的**。
- 指标数字只写“在哪份报告里”，不手抄（coding-standards §9）。命令输出这类验收证据可以贴。

```markdown
- [标题](链接)：看了什么，结论用在哪里。没有就写“无”。

```
