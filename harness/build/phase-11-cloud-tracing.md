# M11：云端实验过程与运行核验

状态：完成（本地与真实云端均已验证，按作者长程任务授权批准）

## 需求

### 目标
- 补齐粗召回、精排、查询分解、各次生成和后处理的过程证据，保留原有检索与回答决策。
- API / MCP 和评测接入可选 Langfuse 云端记录；未配置或上传失败不影响本地记录和回答。
- 实际核验本机配置、数据库和模型，给出启动、出题和长期保存步骤。

### 非目标
- 不读取封存测试题，不改题库、评分和 Prompt，不提前发布尚未完成的正式评测。
- 不迁移业务数据库或预算账本。

### 接口与数据
- 增加 Langfuse SDK 和三项凭据配置；作者本轮明确授权使用免费托管。
- 扩展现有步骤与检索结果的可选详情；沿用 traces.steps JSONB，无表结构迁移。

### 验收标准
- AC1：回归测试覆盖召回与精排候选保留、逐次生成输出、正常与拦截后处理。
- AC2：离线 SDK 替身验证云端步骤、最终回答及评测期望要点；缺凭据不联网，云端故障不改变回答。
- AC3：poe check、poe test-int 通过；核验真实 GPU、DeepSeek、数据库，结果进入 build-log。
- AC4：作者提供 Langfuse 凭据后验证真实上传；缺凭据则明确保留为外部输入阻塞，不宣称已上传。

## 方案

复用 Step、RetrievalResult、TraceRecord 和现有评测缓存。云端适配放 providers，服务逐步发送已完成事件，评测附带原题、金标文档及期望要点。Langfuse 用于开发观测；最终采用 GitHub Pages + JSON/HTML 静态报告，避开托管观测的保留期限制。
