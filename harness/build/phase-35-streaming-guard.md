## 需求

### 目标

1. 生成逐 token 经 SSE 推送，每个事件带递增序号；断线后按序号续推，不丢字、不重复。
2. 入口护栏：日文注入拦截 + PII 脱敏。
3. 出口护栏：禁用表达、数字溯源、引用校验；不通过时撤回并替换为兜底话术。

### 非目标

- 前端。用一个命令行客户端脚本验证断线重连。
- 用模型做出口审核（只用规则和程序校验，保证延迟和可复现）。

### 接口

- `POST /chat`（`stream=true`）事件：`step`（节点进度）、`delta`（文本片段）、`retract`（撤回并给出替换文本）、`answer`（最终完整响应）、`error`。`delta` 起每个事件带 `id: <序号>`，首个事件里带 `response_id`。
- `GET /chat/stream/{response_id}`：带 `Last-Event-ID` 头，从该序号之后补发；缓冲过期返回 410。

### 验收标准

| 编号 | 标准 | 验证 |
|---|---|---|
| AC1 | 首字延迟与整段延迟分别被记录进 trace | 样例 trace |
| AC2 | 在任意序号处断开再重连，拼出的全文与不断线时逐字相同 | 集成测试：随机断点 50 次 |
| AC3 | 客户端收到重复序号时去重后结果不变 | 测试 |
| AC4 | 缓冲在生成结束 120 秒后过期，过期重连得到 410 | 测试 |
| AC5 | 电话、口座番号、卡号、マイナンバー、邮箱在进模型的提示词和日志里都是占位符 | 单元测试 + 检查 trace |
| AC6 | 回答里出现工具返回和检索块里都没有的数字时判不通过并撤回 | 单元测试：构造带错误数字的回答 |
| AC7 | 回答含禁用表达（断定、承诺审查或利率）时撤回 | 单元测试 |
| AC8 | 规程回答的引用都在本次检索结果内且处于生效期 | 单元测试 |
| AC9 | 20 条真实模型样例的撤回比例有实测值 | 记录 |
| AC10 | `poe check`、`poe test-int` 通过 | 命令输出 |

## 任务

- [ ] T1 `providers/`：网关客户端增加流式接口（含用量统计）；假模型支持按片段产出。
- [ ] T2 编排：生成节点用 LangGraph 的流式写出把片段送到 API 层；非流式调用仍可用（评测走非流式）。
- [ ] T3 缓冲：Redis 里按 `response_id` 存片段列表和完成标记；续推接口读取并接上仍在进行的流。
- [ ] T4 心跳：每 15 秒一条注释行；保留现有的 `X-Accel-Buffering: no`。
- [ ] T5 入口护栏：`guard.py` 补日文注入规则；新增 `pii.py`，脱敏在进入图之前完成，trace 里只存脱敏后的文本。
- [ ] T6 出口护栏：数字抽取要处理日文写法（全角数字、「万円」「％」「年月日」、千分位）；比对时做归一化，允许由工具返回数字直接换算得到的常见形式（如 1,234,567 円 与 約 123 万円）——换算规则写成白名单，不要放开到任意运算。
- [ ] T7 撤回：出口不通过时发 `retract`，并把最终 `answer` 设为兜底话术；trace 记录被撤回的原文和原因。
- [ ] T8 命令行客户端：`scripts/stream_client.py`，可指定在第 N 个事件后断开并重连，输出拼接结果。
