# 阶段 31：语料与知识库加工

状态：完成（本地分支 `2026-11-18-build-corpus`）

> 这是计划和记录，不是完成证据；进度以 [build-log](../build-log.md) 为准。设计依据见 [PLANS.md](../../PLANS.md) §3.1、§3.2 和 [GOALS.md](../../GOALS.md)「规模口径」。

## 需求

### 目标

1. 建成日文知识库的三层语料。公开层由执行模型以可见 Chrome 保存，内部层与干扰层使用带标记的合成数据，分成 S、L 两档。
2. 加载、清洗、父子切块、打元数据、嵌入入库 pgvector，并同步进 ES。
3. 规程版本支持两阶段发布（先上新版、再下旧版），重复运行不产生重复块。

### 非目标

- 检索逻辑（阶段 32）。
- 评测题（阶段 36）；但本阶段末尾要导出「出题用语料包」，让作者可以提前出题。

### 约束（必须遵守）

- 公开页面由执行模型操作**有界面的真实浏览器**逐页保存到 `data/raw/public/`，严格按 [PLANS.md §3.1](../../PLANS.md) 的限制：只取清单内页面且不超过 200 页、一次一页、间隔至少 5 秒、不用脚本直接请求、不伪装请求头、不处理验证码、遇到 403 或验证码立刻停。利用条件只允许私人使用，保存的内容不入库。
- 合成文档的事实只能来自公开层；模型不知道的细节宁可不写。每篇合成文档带 `synthetic: true` 和 `based_on`（公开文档 ID 列表）。
- 语料文件不入库。入库的只有脚本、生成提示词、利率表之类的小型种子文件和随机种子。
