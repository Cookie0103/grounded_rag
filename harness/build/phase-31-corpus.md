# 阶段 31：语料与知识库加工

状态：已批准，进行中（本地分支 `2026-11-18-build-corpus`）

> 这是计划和记录，不是完成证据；进度以 [build-log](../build-log.md) 为准。设计依据见 [PLANS.md](../../PLANS.md) §3.1、§3.2 和 [GOALS.md](../../GOALS.md)「规模口径」。

## 需求

### 目标

1. 建成日文知识库的三层语料。公开层由执行模型以可见 Chrome 保存，内部层与干扰层使用带标记的合成数据，分成 S、L 两档。
2. 加载、清洗、父子切块、打元数据、嵌入入库 pgvector，并同步进 ES。
3. 规程版本支持两阶段发布（先上新版、再下旧版），重复运行不产生重复块。

### 非目标

- 检索逻辑（阶段 32）。
- 评测题（阶段 36）；但本阶段末尾要导出「出题用语料包」，让作者可以提前出题。

### 约束（必须遵守）

- 公开页面由执行模型操作**有界面的真实浏览器**逐页保存到 `data/raw/public/`，严格按 [PLANS.md §3.1](../../PLANS.md) 的限制：只取清单内页面且不超过 200 页、一次一页、间隔至少 5 秒、不用脚本直接请求、不伪装请求头、不处理验证码、遇到 403 或验证码立刻停。利用条件只允许私人使用，保存的内容不入库。
- 合成文档的事实只能来自公开层；模型不知道的细节宁可不写。每篇合成文档带 `synthetic: true` 和 `based_on`（公开文档 ID 列表）。
- 语料文件不入库。入库的只有脚本、生成提示词、利率表之类的小型种子文件和随机种子。

### 验收标准

| 编号 | 标准 | 验证 |

| AC2 | 内部层不少于 100 篇，其中带新旧版本的规程不少于 30 组；每月利率通知覆盖至少 24 个月 | 数据报告 |
| AC3 | L 档合计约 3000 篇（±10%），干扰层不含任何评测要用的金标文档 | 数据报告 |

| AC5 | 子块长度分布集中在 300～800 字；表格和条款不被拦腰切断 | 报告里的直方图与 10 个抽样 |
| AC6 | PostgreSQL 与 ES 的块数一致；重复运行入库，新增为 0 | 两次运行的输出 |
| AC7 | 两阶段发布：把一篇规程从 v1 换到 v2 后，按当天日期过滤只能查到 v2，按旧日期过滤只能查到 v1 | 集成测试 |

- [ ] T4 内部层生成：脚本读取公开层，按主题生成操作手册、应对话术、事务规程；每月利率通知用种子利率表套模板。版本组的做法：同一 `policy_id` 前缀，v1 设 `effective_to`，v2 的 `effective_from` 紧接其后，内容里至少有一处可出题的差异（数值、手续、适用条件）。

- [ ] T6 入库：嵌入写 pgvector；块文本和元数据写 ES（索引 mapping 入库）。入库流程幂等，沿用内容哈希。
- [ ] T7 发布：实现 `status` 的 `draft → online → offline` 流转命令。
