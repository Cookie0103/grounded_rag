# 阶段 32：检索

状态：完成（本地分支 `2026-11-18-policy-retrieval`）

> 这是计划和记录，不是完成证据；进度以 [build-log](../build-log.md) 为准。设计依据见 [PLANS.md](../../PLANS.md) §4.3。

## 需求

### 目标

1. 关键词一路从内存 bm25s + jieba 换成 Elasticsearch + kuromoji。
2. 元数据硬过滤：产品线、规程类型、查询日期（生效区间）、语料档，向量和 ES 两路用同一个过滤对象。
3. 用数据决定精排是否默认开启，并拿到 S、L 两档的初步命中率。

### 非目标

- 查询改写、多查询（如需要，在阶段 34 里按延迟预算决定）。
- 正式评测（阶段 36）；本阶段只用一份小的冒烟集。

### 接口

`POST /retrieve` 的 `edition` 参数换成：

```json
{"query": "繰上返済の手数料はいくらですか", "top_k": 5, "rerank": true,
 "filter": {"product_line": "home_loan", "as_of": "2026-11-18", "corpus_tier": "S"}}
```

`as_of` 不传默认当天；`corpus_tier` 不传默认 `L`（全量）。响应结构不变，候选里多返回元数据。

### 验收标准

| 编号 | 标准 | 验证 |
|---|---|---|
| AC1 | ES 一路返回 (chunk_id, 分数)；`policy_id` 能精确命中 | 单元测试 + 集成测试 |
| AC2 | 同一个 `MetaFilter` 生成 SQL 条件和 ES filter，两路过滤结果的块集合一致 | 集成测试：随机 20 组过滤条件比对 |
| AC3 | 失效版本在任何检索模式下都不进入候选 | 版本组的集成测试 |
| AC4 | 冒烟集（执行模型自己写约 30 题，覆盖精确编号、超短问句、口语问法、版本陷阱）上，报四种模式（仅向量、仅 ES、混合、混合加精排）在 S、L 两档的 Top5 命中率、MRR、耗时 | `poe compare-retrieval` 报告 |
| AC5 | 精排默认开或关的决定有数据支撑并写进记录 | 记录 |
| AC6 | ES 不可用时退化为仅向量并标记 `degraded` | 单元测试 |
| AC7 | `poe check`、`poe test-int` 通过；`bm25s`、`jieba3` 依赖已移除 | 命令输出 |

## 记录

- AC1～AC3 经真实 PostgreSQL、Elasticsearch 集成测试验证。用两种日期、两种语料档和五组产品/规程组合，固定覆盖 20 组过滤，双库块 ID 完全一致。全角编号命中指定有效版本，真实 `POST /retrieve` 分别以 2026-10-10 和 2026-11-18 验证 v1、v2，返回 HTTP 200。初次探针发现关键词首位的指定历史规程在融合后落出前五，随后加入精确编号优先级并复验。
- AC4～AC5 在 M4 Max、MPS 上预热后串行执行 `uv run --locked poe compare-retrieval`。数据详见本机 `.cache/phase-32-retrieval-smoke.json`，每档每模式的 30 条请求均无时间区间无效候选，表中延迟仅含检索。

| 模式 | S 命中数 | S MRR | S P95（ms） | L 命中数 | L MRR | L P95（ms） |
|---|---:|---:|---:|---:|---:|---:|
| 向量 | 24/30 | 0.7000 | 39.33 | 24/30 | 0.7000 | 41.29 |
| Elasticsearch | 28/30 | 0.8917 | 8.94 | 28/30 | 0.8917 | 10.62 |
| 混合 | 30/30 | 0.9778 | 38.62 | 30/30 | 0.9778 | 41.88 |
| 混合加精排 | 27/30 | 0.7472 | 1964.51 | 27/30 | 0.7472 | 1993.04 |

- 本轮默认混合且关闭精排。混合检索在 S/L 的节点中位耗时分别为嵌入 23.99/24.92 ms、向量 7.34/8.47 ms、关键词 5.15/4.90 ms，精排开启时节点中位耗时为 1571.28/1650.78 ms。沿用 kuromoji 默认词典设置。
- 旧英文指令的纯向量检索两档均 25/30，MRR 0.6639；新日文指令两档均 24/30，MRR 0.7000。保留日文指令，记录这组冒烟题上的命中取舍。
- AC6 用故障替身验证 ES 无法查询时调用同一过滤条件下的 pgvector，响应标记 `degraded` 并跳过精排。
- AC7 `uv lock --check` 解析 172 个包。忽略全局 uv 配置的 `uv run --locked poe check` 通过 445 个测试，覆盖率 92.46%；`uv run --locked poe test-int` 通过 34 个测试。BM25 与中文分词的 18 个专属测试随对应实现归档，检查门槛未变化。
