# 阶段 35 决策记录

记录日期：2026-11-18

- SSE 生产任务独立于连接，由 API 生命周期管理。Redis Streams 保存同一响应的全部事件，服务器用 Lua 原子追加并分配连续序号。读端沿 `Last-Event-ID` 继续，空闲每 15 秒心跳。终态后保留 120 秒，运行中另有清理期限。API 退出时结束未完成的生产任务，本机 PoC 的恢复范围为连接中断。
- 网关 SSE 只推可显示的文字。模型结束事件包含网关返回的真实 token 用量，按原配置记账。上游流中断后收口，避免重复发起已经开始的流式模型请求。
- 所有用户问题在进入问答图和追踪之前脱敏。工作台权限判断仍用独立的坐席和客户 ID，已存的上一轮规程问题在读取时也会再脱敏。
- 出口校验使用本次模型实际获得的证据：已裁剪工具结果和规程块。数字按类型比较，精确单位归一化，支持有「約」的整万四舍五入和从同一日期提取局部日期。引用必须在实际编号表内，日期使用查询的 `as_of`。
- 模型文字逐片可见，完整检查后必要时发 `retract`。脱敏后的原文和原因在本机 trace 保留，问答进度和终态响应隐藏该诊断文本。使用合成业务数值或引用合成规程的问答带 `synthetic` 标记。
- 服务 trace 记录产生第一段可显示文本和组装完回答的时间。HTTP 冒烟同时从客户端计时到收到第一段及最终 `answer`，包含本机 HTTP、Redis 推送和 trace 持久化等额外开销。没有流式文本的同步调用只记录整段耗时。
