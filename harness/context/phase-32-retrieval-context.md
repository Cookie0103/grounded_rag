# 阶段 32 检索决策

- pgvector 与 Elasticsearch 在检索前执行相同的产品线、规程类型、语料档与日期条件。融合后的候选从 PostgreSQL 实时回读并复验过滤条件，避免版本发布时 ES 快照暂未更新造成过期候选。常驻服务保留查询向量缓存，规程检索结果逐次按当时的元数据查询。
- 请求里有明确规程编号时，关键词一路提升精确匹配，融合与精排后继续保留有效的精确匹配优先级。向量消融路径保持纯向量排名。
- `/retrieve` 采用新版过滤与响应元数据。旧 `/chat`、MCP 兼容签名及旧数据库字段保留到对应迁移阶段。旧检索冒烟夹具仍由传统压测命令及指标测试使用，阶段 36 更换这些调用点时处理。
- 正常检索默认混合、关闭精排，显式 `rerank=true` 可启用。当前决定依据 30 条日文冒烟，正式阶段会独立评测。
