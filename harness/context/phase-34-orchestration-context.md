# 阶段 34 决策记录

记录日期：2026-11-18

- 坐席和客户分别编译 LangGraph。坐席以函数调用选择只读工具，最多两轮，相互独立的工具并发。规程与查数可并行，任一必需工具失败或无权查询时用固定日文话术收口。客户图不挂工具节点，碰到查数或含查数的混合请求时转人工。
- 意图模型只收到当前问题和上一轮意图。本机 LiteLLM 转发给 Ollama 时，带 `logprobs` 的真实请求返回 HTTP 400；只带 JSON 模式的分类返回 HTTP 200，带 `tools` 的规划也返回 HTTP 200。小模型连接省略不支持的参数，按输出是否合法走正常分类或保守规程路径。可以提供真实 logprobs 的连接只用主意图值对应的 token 计算置信度。
- 默认用本机网关，小档为 Ollama Qwen3 4B Instruct，生成档为 DeepSeek V4 Pro。保留旧的直连配置作为历史评测选项。严格模式继续使用原证据评分、忠实度提示词，按需开启，默认关闭。
- 使用 `langgraph-checkpoint-postgres` 的异步 saver 和 psycopg。检查点图只保存上一次意图和最近的规程问题，和问答图的业务工具数据隔离。路由按泳道及工作台作用域构造会话键后散列，单 worker 对同一会话顺序执行。多个 worker 的同会话轮次顺序留待部署时处理。
- 本机旧 `sessions` 表查询为 0 行，迁移 0007 退役该空表。其他安装如有旧会话则改名保留，降级迁移可以恢复表名。原来的 `self_host` / `cloud` 筛选转为规程 `MetaFilter`。保留旧观测存储的 `route` 等字段用于历史追踪，HTTP 回包使用 `intent`。
- 完整回答不跨请求缓存，避免工作台数据和规程版本被误复用。工具数据仍按阶段 33 的短时 Redis 缓存复用。旧的人工干预库存储和管理命令保留，双泳道不再用旧版预置答案绕过编排。
