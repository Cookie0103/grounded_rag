# 阶段 33 决策记录

记录日期：2026-11-18

- 模拟业务用独立 FastAPI 和 `aiomysql`，通过 HTTP 与问答服务连接。Compose 等到 MySQL 健康再启动模拟服务。启动时拿 MySQL 命名锁、建缺失的表，并在一个事务中灌入合成种子。再次启动保留现有数据，`mock_core.seed verify` 可以校验全表指纹。
- 种子编号为 `33`，合成业务基准日为 `2026-11-18`。商品、金利类型和団信使用本机公开层里的称谓，金额、利率、优惠内容、人员、合同和归属均为编造的测试数据。工具成功结果保留 `synthetic: true`。
- 问答端每次先检查坐席、工作台客户及可选合同的归属，再查 5 秒 Redis 缓存。工具层对 Redis 键中的身份和参数做散列。模拟服务在业务查询时独立复核归属。故障注入默认关闭，集成测试显式开启请求头，正式对照再按评测场景配置。
- 无区间的还款明细从下一次还款日取最多五期，已完济时取最后五期。显式区间取该区间的前五期。结果都保留裁剪前的 `total`。工具 trace 只存调用名称、耗时、状态、缓存、返回数量和区间摘要。
- 裁剪 token 统计使用已有的 `Qwen/Qwen3-Embedding-0.6B` tokenizer 在本机离线编码紧凑 JSON，两侧均用 `synthetic`、`data`、`total` 外层字段，计算时关闭特殊 token。这个样例用于比较同一份业务载荷的大小，成本记录仍取网关实际回传用量。
